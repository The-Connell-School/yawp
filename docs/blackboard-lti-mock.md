# Blackboard LTI 1.3 platform mock

YAWP is the LTI **Tool**. This mock impersonates Blackboard Learn as the LTI 1.3 **Platform**, including LTI Advantage Assignment and Grade Services and Deep Linking. It exists so launch, grade passback, Deep Linking, and every documented failure mode can be built and tested without a Blackboard tenant.

It is a mock and test harness only. It does not implement YAWP's Tool integration.

## Run it locally

From a worktree that has already been bootstrapped (`bash scripts/worktree-local-setup.sh`):

```bash
bun blackboard-lti-mock
bun dev
```

The setup script writes `BLACKBOARD_LTI_MOCK_URL` into `services/web-app/.env` and prints the mock port.

- Direct Learn UI: `http://localhost:<LTI_MOCK_PORT>/`
- Same-origin Learn UI (dev flask menu **Blackboard**): `http://localhost:<DEV_PORT>/dev/blackboard-lti-mock/`

`bun blackboard-lti-mock` sets `BLACKBOARD_LTI_MOCK_ENABLED=true`. The process refuses to start without that flag.

Sign in as **Ada Student** or **Grace Instructor**. There is one seeded course, ENG-101 English Composition, with a Yawp Assignment content link. Students open that link and check **My Grades**. Teachers open the same link, see **Gradebook**, and can **Add teaching tool** (Deep Linking). Fault injection is not in the UI; use query `?fault=` or header `X-Yawp-Lti-Fault` on the protocol endpoints.

## Run it in a preview

PR previews do not use a repo-root `docker-compose.yml`. Compose files are generated by `scripts/preview/render-compose.mjs` and started by `scripts/preview/deploy.sh`.

This mock is a sibling Compose service named `blackboard-lti-mock`:

- Image: `oven/bun:1.3.1` with the preview source bind-mounted (same pattern as the fast `web` service)
- Command: `bun scripts/blackboard-lti-mock/server.mjs`
- The web container receives `BLACKBOARD_LTI_MOCK_URL=http://blackboard-lti-mock:9473`
- After `web` is recreated, deploy starts the mock only when the rendered compose file contains that service, so older application refs stay deployable

Open the flask menu in the preview and choose **Blackboard**, or go to `/dev/blackboard-lti-mock/`. That path is an app-side reverse proxy, so the existing preview access gate stays in front of Learn. Each preview also gets a public Learn host, `https://blackboard-pr-<number>.$PREVIEW_DOMAIN` (for example `https://blackboard-pr-291.preview.yawp.school`). Sign in as a student or a teacher; the preview does not show a harness control panel. The production App Runner image does not copy `scripts/` and does not start this process.

## Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `BLACKBOARD_LTI_MOCK_ENABLED` | unset (required `true`) | Process-level enable switch |
| `BLACKBOARD_LTI_MOCK_PORT` / `PORT` | `9473` | Listen port |
| `BLACKBOARD_LTI_MOCK_HOST` | `0.0.0.0` | Listen host |
| `BLACKBOARD_LTI_MOCK_ISSUER` | `https://blackboard.com` | Platform `iss` (Blackboard's real issuer is this URL, not the Learn host) |
| `BLACKBOARD_LTI_MOCK_CLIENT_ID` | `yawp-blackboard-mock` | Tool client id / `aud` |
| `BLACKBOARD_LTI_MOCK_DEPLOYMENT_ID` | `yawp-mock-deployment` | `deployment_id` |
| `BLACKBOARD_LTI_MOCK_PLATFORM_GUID` | `yawp-blackboard-mock-guid` | `tool_platform.guid` |
| `BLACKBOARD_LTI_MOCK_PUBLIC_URL` | request-derived | Public origin used inside AGS/NRPS/Deep Linking URLs |
| `BLACKBOARD_LTI_MOCK_PUBLIC_BASE_PATH` | empty | Prefix when Learn is reverse-proxied (`/dev/blackboard-lti-mock` in preview) |
| `BLACKBOARD_LTI_MOCK_TOOL_REDIRECT_URI` | `http://127.0.0.1:5176/lti/launch` | Tool redirect URI (YAWP's future launch URL) |
| `BLACKBOARD_LTI_MOCK_TOOL_OIDC_LOGIN_URL` | `http://127.0.0.1:5176/lti/login` | Tool OIDC login initiation URL |
| `BLACKBOARD_LTI_MOCK_TOOL_JWKS_URL` | empty | Tool JWKS used to verify client assertions and Deep Linking responses |
| `BLACKBOARD_LTI_MOCK_TOOL_JWK` | empty | Inline Tool public JWK JSON (tests / local without a JWKS server) |
| `BLACKBOARD_LTI_MOCK_TOKEN_TTL_SECONDS` | `60` | AGS access-token lifetime so expiry/caching is exercisable |
| `BLACKBOARD_LTI_MOCK_TIMEOUT_MS` | `35000` | Delay used by the `ags_timeout` fault |
| `BLACKBOARD_LTI_MOCK_URL` | unset | Web app only: upstream URL for the same-origin Learn proxy |
| `YAWP_ENVIRONMENT` | unset | `production` is always refused; `preview` is allowed even when `NODE_ENV=production` |
| `NODE_ENV` | unset | `production` is refused unless `YAWP_ENVIRONMENT=preview` |

RSA keypairs are generated at boot. They are never logged, never written to disk, and never included in JWKS or the event log.

## Values to plug into YAWP's (future) Tool config

Point the Tool at the mock, not at developer.blackboard.com:

| Tool setting | Mock value |
| --- | --- |
| Issuer (`iss`) | `https://blackboard.com` |
| Client ID | `yawp-blackboard-mock` |
| Deployment ID | `yawp-mock-deployment` |
| Public keyset / JWKS | `{origin}/api/v1/management/applications/yawp-blackboard-mock/jwks.json` |
| OIDC auth request endpoint | `{origin}/api/v1/gateway/oidcauth` |
| Auth token endpoint | `{origin}/api/v1/gateway/oauth2/jwttoken` |
| Tool OIDC login URL (register this on the mock via env) | `{app}/lti/login` |
| Tool redirect URI | `{app}/lti/launch` |
| Tool JWKS URL | `{app}/lti/jwks` |

Local `{origin}` is `http://127.0.0.1:<LTI_MOCK_PORT>`. In a preview, server-side Tool calls (JWKS, token, AGS) must use `http://blackboard-lti-mock:9473`. Browser redirects use the public preview URL. AGS/NRPS URLs inside the `id_token` are minted with the internal origin so the Tool container can call them.

## Launch configuration

Drive user, role, course, and resource link with query parameters on `/dev/launch` or `/api/v1/gateway/oidcauth`:

- `role` — `Learner` / `Instructor` / `Administrator` (also accepts `student`, `teacher`, `admin`)
- `sub`, `context_id`, `context_label`, `context_title`
- `resource_link_id`, `resource_link_title`
- `message_type` — `LtiResourceLinkRequest` (default) or `LtiDeepLinkingRequest`
- `kid` — sign with a specific published key (key-rotation tests)
- `format=json` — return `{ id_token, state }` instead of the auto-submitting form

The Learn UI signs in as Ada Student or Grace Instructor and opens those values from course content. `/dev/launch` still accepts the query parameters below for tests.

## Fault triggers

Set **one** of: query `?fault=...` or header `X-Yawp-Lti-Fault: ...`. Names are stable:

| Fault | What the mock does |
| --- | --- |
| `expired_launch` | Valid RS256 `id_token` whose `exp` is already in the past |
| `replayed_nonce` | Reuses a nonce the mock already issued |
| `invalid_jwt` | Tampered signature |
| `mis_signed_jwt` | Signed with a key that is **not** in JWKS |
| `unknown_deployment` | `deployment_id` is not the configured deployment |
| `wrong_audience` | `aud` is not the Tool client id |
| `token_endpoint_failure` | Token endpoint returns 503 |
| `ags_403_missing_scope` | AGS returns 403 even if the bearer token is otherwise valid |
| `ags_5xx` | AGS returns 503 |
| `ags_timeout` | AGS waits `BLACKBOARD_LTI_MOCK_TIMEOUT_MS` before responding |

AGS also returns 403 on its own when the access token is missing the required scope. That is the non-forced missing-scope path.

## Production impossibility

Enforced in `scripts/blackboard-lti-mock/production-guard.mjs`, not by convention:

1. Refuses `YAWP_ENVIRONMENT=production`
2. Refuses `NODE_ENV=production` unless `YAWP_ENVIRONMENT=preview` (preview production-runtime containers use `NODE_ENV=production`)
3. Refuses to start unless `BLACKBOARD_LTI_MOCK_ENABLED=true`
4. The production Dockerfile `CMD` is still `services/web-app/start.sh` and does not copy `scripts/`

The same-origin Learn proxy additionally returns 404 unless local-dev/preview auth is enabled and `BLACKBOARD_LTI_MOCK_URL` is set.

## Tests

```bash
bun test ./scripts/blackboard-lti-mock/ --timeout 60000
```

CI runs that command in the Prisma/deployment-contract job. The tests sign and verify real RS256 JWTs against the mock JWKS, reject bad Tool assertions, store scores idempotently by timestamp, and fire every fault above.

## What this mock does not pretend to be

- **Names and Roles Provisioning Service** is advertised in the launch claim (Blackboard includes that block) but the memberships collection is not implemented. Roster sync is out of scope for this harness.
- **Learn REST (non-LTI)** application key/secret OAuth is not implemented. LTI Advantage uses the JWT client-assertion token endpoint above, which is a different security model.
- **Cookie/CSRF `state` checking** is the Tool's job. The mock echoes `state` on the form post.
- **NRPS, submission review, and platform-originating line-item edits** are not fully simulated. Score POST is write-only per IMS; use `GET /dev/scores` to assert what the mock received.
